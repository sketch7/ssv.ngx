# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`@ssv/ngx` (repo `ssv.ngx`) is an Nx monorepo publishing two independent Angular utility libraries to npm:

- `@ssv/ngx.command` — the command pattern (loading/disabled state for actions), consumed elsewhere in
  Sketch7's ecosystem (e.g. `sketch7.arcane.cosmowrench` uses it for button loading state).
- `@ssv/ngx.ux` — viewport/responsive utilities (breakpoint matching, SSR-aware device detection).

Built with Angular 21+, TypeScript 5.9, Nx 22, and Vitest 4. `apps/test-app` is a dev harness app (served
via `@angular/build:dev-server`) used to manually exercise both libraries side by side — it is not
published and has no other consumers.

Canonical AI-agent instructions already live in `.github/copilot-instructions.md` (architecture, the
command pattern, viewport utilities, testing, known issues) and `AGENTS.md` (Nx task-running rules). This
file summarizes and points to those rather than duplicating them in full — read
`.github/copilot-instructions.md` for the deepest detail.

## Commands

Package manager is **pnpm** (enforced via a `preinstall` guard — `npx only-allow pnpm`). Node >=24.14.0.

```bash
pnpm install

pnpm start                       # = nx serve test-app — dev harness app
pnpm run build                   # = nx run-many -t build — builds both libs to dist/libs/{lib-name}
pnpm run lint                    # = nx run-many -t lint
pnpm test                        # = nx run-many -t test — all libs, via Nx (cached)
pnpm nx test ngx.command         # test a single lib (per libs/ngx.command/package.json scripts)
pnpm nx lint ngx.command         # lint a single lib
pnpm nx build ngx.command        # build a single lib

# Root vitest.config.ts treats each lib under libs/* as a vitest "project", so a single spec can
# also be run directly (each lib config sets test.name to its npm package name, e.g. "@ssv/ngx.command"):
pnpm vitest run libs/ngx.command/src/command.spec.ts
pnpm vitest run --project="@ssv/ngx.command"

pnpm nx reset                    # clear the Nx cache when builds/tests seem stale
```

Always run tasks through `nx` (`nx run`, `nx run-many`, `nx affected`) rather than calling the underlying
tool directly — this is an explicit rule in `AGENTS.md`. Nx MCP tools (`nx_workspace`, `nx_project_details`,
`nx_docs`, `nx_cloud_cipe_details`, etc.) are available and preferred over guessing at Nx config/CLI flags.

### Release / publish

```bash
pnpm run pre-release-build   # local: nx release version $VERSION — bumps package.json + version.ts in both libs
pnpm run release             # CI only: nx release publish — publishes dist/libs/{lib} to npm
```

- `nx.json` `release.projects` is `["libs/*"]`; both libraries share the root `package.json` version (kept
  in sync by `nx release version`) and each has its own generated `src/version.ts` exporting `VERSION`.
  `pre-release-build` expects a `$VERSION` env var/argument.
- CI publishes on `master`, `*.x` branches, or manual workflow trigger.
- Version compatibility is tied to Angular majors: Angular 17+ -> v3.x+, Angular 10-16 -> v2.x,
  Angular 4-9 -> v1.x (see `CHANGELOG.md` for the version history and breaking-change notes per release).

## Architecture

### Lib layout (per-library, not per-file)

Both libs follow the same shape — use `libs/ngx.command` and `libs/ngx.ux` as the reference pair for any
new library:

```
libs/{lib}/index.ts              # re-exports "./src/index" — the ng-packagr entry point
libs/{lib}/src/index.ts          # the ONLY public surface — hand-curated named exports (not `export *`
                                  #   at this level for ngx.command; ngx.ux re-exports whole submodules)
libs/{lib}/src/version.ts        # generated by `nx release version`, exports VERSION
libs/{lib}/src/*.ts              # implementation — directives, services, models, utils
libs/{lib}/src/*.spec.ts         # co-located Vitest specs (not a separate __tests__ dir)
libs/{lib}/ng-package.json       # ng-packagr config; dest -> dist/libs/{lib}
libs/{lib}/project.json           # Nx targets: build (@nx/angular:package), test (@nx/vitest:test), lint
libs/{lib}/package.json           # publishable package manifest (name, peerDependencies, keywords)
libs/{lib}/vitest.config.ts       # per-lib Vitest project config (sets test.name to the npm package name)
```

`libs/ngx.ux` additionally nests a `viewport/` (and `viewport/viewport-data/`) submodule folder, each with
its own `index.ts` barrel re-exported from the lib's top-level `src/index.ts` — the pattern for splitting a
larger lib into sub-features while keeping one public entry point.

**No cross-dependencies between the two libraries** — each publishes and versions independently, and Nx
module boundaries enforce this at lint time. When adding a new public export, always add it to the lib's
`src/index.ts` barrel explicitly (named exports); don't rely on deep imports.

### Command pattern (originates in this repo — `libs/ngx.command`)

This is the reference implementation consumed as `@ssv/ngx.command` by other Sketch7 apps (e.g.
cosmowrench). Core shape:

- `command(execute, canExecute?)` — factory function (not `new Command()`) that auto-injects `DestroyRef`,
  so no manual cleanup is needed. Handles sync and async (`Promise`/`Observable`-returning) execute
  functions automatically, exposes signal state (`isExecuting`, `canExecute`).
- `canExecute` accepts a `Signal`, `Observable`, plain `Function`, or `boolean`.
- `SsvCommand` / `SsvCommandRef` directives wire a command to a `<button>` (`[ssvCommand]`), with
  `[ssvCommandParams]` for arguments — arrays must be double-wrapped (`[[arr]]`) to avoid being spread as
  multiple params.
- `commandAsync` and the `Command` class remain exported but are `@deprecated` in favor of `command()` —
  the repo's convention for deprecating APIs is a `/** @deprecated Use {@link x} instead. */` re-export
  alias that keeps backward compatibility rather than a breaking removal.

### DI and coding conventions (enforced throughout, not just command)

- `inject()` only, never constructor injection; private fields use the `#` prefix (e.g.
  `#renderer = inject(Renderer2);`).
- Standalone only — no NgModules in new code (existing `*.module.ts` files like `command.module.ts` /
  `ux.module.ts` are kept for backward-compatible consumers, not a pattern to extend).
- Signals over decorators: `signal()`/`computed()`/`effect()`, `DestroyRef` over `ngOnDestroy`.
- Double-quoted strings (`@stylistic/ts/quotes` eslint rule); prefer `unknown` over `any`.
- Custom `ssv` selector prefix (see `prefix: "ssv"` in each lib's `project.json`).

### Testing (Vitest, not Jasmine/Karma)

Despite `nx.json` generator defaults listing `unitTestRunner: "jest"`, the libraries actually run on
**Vitest 4** via `@nx/vitest:test` (each `project.json` overrides the generator default). Angular test
environment is bootstrapped in each lib's `src/test-setup.ts` via `@analogjs/vitest-angular/setup-zone` +
`getTestBed().initTestEnvironment(BrowserTestingModule, platformBrowserTesting())`. Specs live next to the
source file they test (`*.spec.ts`), not in a separate test tree.

### Known issue worth knowing before touching structural directives

Angular 21's `TemplateRef` typing causes `TS2322` on `*ssvViewportMatcher="...; else foo"` — the workaround
used throughout this repo is two separate structural directives (positive + negated condition) instead of
an `else` clause.
